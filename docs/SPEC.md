# MeOS — 개인 통합 대시보드 ("Personal OS")

> 기획/설계 문서 (v1) · 최종 갱신 2026-08-11 (앱 이름 MeOS 로 변경)

## 1. 개요

구글 캘린더 · 사내 Redmine · 회사 JIRA · intervals.icu 의 데이터를 **한곳에 모아 조회**하는
개인용 통합 대시보드. **PC 데스크톱 앱**이 메인이고, **모바일 브라우저(PWA)에서도 조회** 가능하며,
개인 데이터는 **클라우드에 동기화**되어 어느 기기에서든 같은 화면을 본다. 단, **회사 업무 정보는
데스크톱에서만 다루고 클라우드/모바일로 내보내지 않는다.**

## 2. 핵심 원칙

- 모든 외부 연동은 **읽기 전용 (조회/집계)** — 앱에서 원본 서비스로 쓰기(write-back)는 하지 않음.
  **예외: Perforce** — CL 간 파일 이동(`p4 reopen`)과 CL 설명 저장(`p4 change -i`)은 쓰기다 (§3.3).
  서밋(`p4 submit`)은 구현하지 않는다.
- **데이터 2계층 분리**:
  - **개인 데이터**(구글 캘린더 · 운동 · 리포트 · 업무 메모/할 일/루틴) → 클라우드 DB 저장, **PC·모바일 공용**.
  - **BTS 이슈 목록**(Redmine · JIRA) → **데스크톱 전용 · 실시간 조회, DB/클라우드 미저장, 모바일 미노출.**
- **모바일은 조회 위주** → 네이티브 앱 대신 반응형 웹/PWA로 충분. (2026-08-11 PWA 적용, §11)

> ⚠️ **원칙 변경 (2026-08-07)** — 원래는 "회사 업무 정보는 클라우드에 절대 올리지 않는다" 였으나,
> 진행 중인 업무 목록을 PC·모바일에서 동일하게 보기 위해 **사용자 결정으로 완화**했다.
> - **여전히 클라우드에 안 올라가는 것**: BTS 이슈 목록 전체(실시간 조회 결과), Redmine/JIRA 접속 토큰.
> - **클라우드에 올라가는 것**: 내가 직접 *진행 중인 업무로 끌어다 놓은* 항목의 이슈번호·제목·트래커·목표버전.
>   즉 "내가 지금 붙잡고 있는 일" 몇 건만 올라가고, 이슈 본문·댓글·첨부는 올라가지 않는다.

### 3.1 운동 모듈 화면 구성

기준 레이아웃은 `reference/1783334079.png` 를 따르되, 아래 변경을 적용한다.

- **상단 KPI 카드(4개)**: 이번 달 마일리지·회수 / 이번 주 거리(지난주 대비) / 이번 주 운동 횟수 / 이번 주 시간
- **좌측 상단 — 주간 거리**: 최근 8주 막대그래프 (주간/월간 토글)
- **좌측 하단 — 최근 활동**: 테이블 (날짜·종류·거리·시간)
- **우측 상단 — 종류별**: 최근 활동 기준 Run/Walk 등 요약 바
- **우측 하단 — (변경) 기본 = Fitness 그래프**:
  - 기본 표시는 intervals.icu **Fitness 그래프 = 훈련부하 추이**(Fitness/CTL · Fatigue/ATL · Form/TSB).
  - 차트 아래 **범례 항목에 마우스를 올리면 그 지표가 무슨 뜻인지 설명 툴팁**이 뜬다
    (CTL=42일 평균 “체력”, ATL=7일 평균 “피로”, TSB=CTL−ATL “컨디션” + 대략적인 해석 구간).
    Recharts 기본 `<Legend>` 대신 직접 그린 범례라 hover/포커스/탭(터치) 모두 동작한다.
  - 이 패널에 **[러닝화 보기]** 버튼을 둔다 → 누르면 **러닝화 장비 마일리지** 목록으로 토글(또는 드로어/모달).
  - 즉 러닝화 지표는 상시 노출이 아니라 **버튼을 눌렀을 때만** 확인.
  - 러닝화 데이터 소스 = **Garmin 별도 연동(후순위)**. Phase 1에선 버튼/자리만 잡고 gear 연동은 후속 Phase에서 채운다.

### 3.2 업무 모듈 화면 구성

기준 레이아웃은 `reference/1786073610.png`. 위에서부터 4개 섹션(모두 접이식 카드).

1. **진행 중인 업무** — 대기 / 진행 / 완료 **3개 그룹**이 각각 드롭 영역이다.
   그룹 사이로 끌어 놓으면 상태가 바뀐다. 하단 입력으로 직접 추가하면 *대기*로 들어간다.
   입력에 URL이 섞여 있으면 링크로 분리해 제목만 표시한다.
   행 앞의 **상태 칩을 누르면 한 단계씩 넘어간다: 대기 → 진행 → 완료 → (다시) 대기.**
   마지막에서 대기로 도는 건 칩만으로도 왕복할 수 있게 하기 위함이고, 임의 이동은 드래그로 한다.
2. **BTS — 버그 트래커 (Redmine / JIRA)** ⚠️**데스크톱 전용** — 내 담당 이슈를 실시간 조회.
   트래커 탭(개발/버그 …)은 실제 데이터에서 뽑고, 목표버전 필터 + 버전순 정렬을 제공한다.
   행을 **‘진행 중인 업무’로 끌어다 놓으면** 이슈번호·제목·트래커·목표버전이 채워져 등록되고,
   **BTS 목록에는 그대로 남으면서** 해당 행이 강조 표시된다. 반대 방향(진행 중 → BTS) 이동은 없다.
3. **할 일 (BTS 외)** — BTS와 무관한 할 일. **‘진행 중인 업무’와 서로 드래그 이동 가능**.
   목록 안에서 **드래그로 순서 변경** 가능.

**순서 변경** — 할 일·루틴은 행을 끌어 목록 순서를 바꾼다. 지나가는 행 위에서 자리가 실시간으로 바뀌고,
드래그가 끝날 때 한 번에 저장한다. 새 `sort` 는 **이웃 사이 중간값**이라 보통 한 행만 갱신되며,
중간값을 반복해 쪼개 double 정밀도가 바닥나면 그 목록 전체를 `0·1000·2000…` 으로 다시 매긴다
(계산은 `web/src/lib/reorder.ts` 의 순수 함수 `computeReorder`).

**등록 후 수정** — 진행 중인 업무·할 일 항목은 행의 연필 버튼(마우스 올리면 표시)으로 제목을 고칠 수 있다.
링크가 없는 항목은 제목 더블클릭으로도 편집한다(링크가 있으면 클릭이 ‘열기’라서 겹치지 않게 제외).
Enter/포커스 아웃 = 저장, Esc = 취소, 빈 제목은 무시. 편집 입력도 추가 입력과 같은 규칙이라
`제목 https://…` 형태로 링크까지 한 줄에서 고칠 수 있다(BTS 유래 항목은 원본 이슈 링크를 유지하고 제목만 변경).
4. **루틴 (매일 리셋)** — 체크로 완료 표시. **드래그로 순서 변경** 가능.
   `last_done_on` 이 오늘이 아니면 자동으로 풀리므로
   **별도 리셋 배치가 필요 없다**. 앱을 켜둔 채 자정을 넘겨도 화면이 스스로 갱신된다.

**휴지통** — 이 화면에서 만든 항목(진행 중인 업무 · 할 일 · 루틴)과 **바로가기 · 스니펫**은
삭제 시 사라지지 않고 휴지통으로 이동한다. 별도 `휴지통` 화면에서 **복원 / 영구 삭제** 가능.
클라우드 항목은 soft delete(`deleted_at`), 바로가기·스니펫은 PC 로컬 휴지통에 보관된다.

### 3.3 Perforce 모듈 ⚠️데스크톱 전용

`p4` CLI 를 Electron main 에서 실행한다(`electron/p4.js`). 사내망 + 로컬 워크스페이스가 필요해 데스크톱 전용.

- **Pending 목록** — 선택한 워크스페이스의 체인지리스트만 조회한다(`p4 changes -s pending -c <ws>`).
  번호 없는 **default 체인지리스트**는 `p4 changes` 에 안 나오므로 `p4 opened` 결과에서 만들어 낸다.
- **CL 간 파일 이동** — 드래그앤드롭 → `p4 reopen -c`. ⚠️ **이 프로젝트에서 유일한 외부 서비스 쓰기 작업**
  (§2 "모든 외부 연동은 읽기 전용" 의 예외). 서밋(`p4 submit`)은 되돌리기 어려워 **구현하지 않는다**.
- **서밋 로그 AI 작성** — CL 선택 → 변경 파일 + diff + **내 과거 서밋 이력**을 **사내 LLM** 에 보내
  아래 양식으로 받고, 사용자가 고친 뒤 `p4 change -i` 로 CL 설명에 저장한다.

**서밋 로그 양식** (사용자 지정)

```
[김건훈][토너먼트]
- #29580
- 메뉴 탭 숨김 처리 수정 : WBP 에서 탭이 오버레이로 한 번 더 감싸여 있어 …
- WBP : 토너먼트 메인 UI 구성 수정
```

- **`[이름]`** — 설정값(`userName`), **항상** 맨 앞에 붙는다. LLM 이 아니라 코드가 붙인다.
- **`[컨텐츠]`** — 같은 파일들의 과거 서밋 중 `[이름][컨텐츠]` 패턴에서 따온다(`p4 changes -l <files>`).
  이력이 없으면 파일 경로에서 유추하고, 애매하면 생략한다.
- **`- #번호`** — 같은 이력에서 찾은 작업번호. ⚠️ **이력에 없는 번호는 코드가 버린다** —
  틀린 번호를 쓰느니 비우는 편이 낫기 때문. 모델이 지어내면 UI 에 "제외했다" 고 알린다.
- **항목** — `짧은 제목 : 구체적 설명` 형태.
- **바이너리 파일**(`.uasset`/`.umap` 등) — diff 가 무의미하므로 **diff 를 시도하지 않고**
  `WBP : 토너먼트 메인 UI 구성 수정` 처럼 파일 종류 + 한 줄 요약만 적는다(내부 추측 금지).

모델 출력은 `{content, issue, items[]}` JSON 으로 받고 **양식 조립은 코드가 한다**(`llm.composeLog`).

**AI 코드 리뷰** ⚠️Windows 전용 (2026-08-14 추가)

CL 마다 `AI 리뷰` → 설정에 켜 둔 리뷰어 1~N 개에게 **같은 프롬프트를 동시에** 보내고, 결과를 md 한 벌로
로컬에 저장한다. `리뷰 보기`(그 CL) / `리뷰 기록`(전체)에서 다시 보고 지운다.

| 종류 | 실행 | 설정 가능 | 코드 전송 |
| --- | --- | --- | --- |
| `codex` | `codex exec -` CLI | model · reasoning effort(low~xhigh) | **사외** |
| `claude` | `claude -p` CLI | model · effort(low~max) | **사외** |
| `local` | 사내 LLM (OpenAI 호환) | model | 사내망 |

- **auth 방식 고정** — API 키가 아니라 이미 로그인해 둔 구독 계정을 쓴다. 그래서 자식 프로세스 환경에서
  `ANTHROPIC_*` / `OPENAI_*` 키를 지운다(`review.API_ENV_KEYS`). 남아 있으면 CLI 가 로그인 대신 키를 쓴다.
- **입력은 셋 다 동일** — diff + 신규 파일 본문 + 파일 목록. 리뷰어가 워크스페이스를 뒤지지 않게
  `claude --tools ""` · `codex --sandbox read-only` 로 도구를 막는다(결과 비교가 목적).
- **신규 파일**은 `p4 diff` 가 비어 있으므로 `p4 opened` 의 `clientFile` 로 로컬 파일을 직접 읽는다
  (`p4.readNewFiles`). 서밋 로그와 달리 리뷰에서는 신규 파일이 핵심이다.
- **저장** — `CL29580_20260814-153012.md` (파일명에 시각). 프론트매터에 CL·시각·리뷰어·성공/실패를 적어
  목록을 파일만 읽고 만든다(`reviewStore`). 기본 위치 `userData/reviews`, 설정에서 변경 가능.
- 렌더러가 넘긴 파일 목록은 믿지 않는다 — `review:run` 은 `p4 pending` 을 다시 조회한다(로컬 경로 필요 + 최신성).
  파일명도 `^[A-Za-z0-9_.-]+\.md$` 로 검증해 경로 탈출을 막는다.
자유 형식으로 받으면 이름·대괄호·불릿이 매번 흔들리기 때문.
P4USER 가 공용 계정이라 "내 서밋" 구분은 설명의 `[이름]` 접두어로 한다.

**이 서버의 함정 (실측)**
- `P4USER` 가 **공용 계정**(`client`)이라 사용자 구분이 안 된다 → 조회는 반드시 **워크스페이스** 기준.
- 워크스페이스가 **Host 로 잠겨** 있다(`Client 'X' can only be used from host 'Y'`).
  90개가 넘어 설정 화면에서 **이 PC에서 쓸 수 있는 것만** 걸러 보여준다.
- `P4CHARSET=utf8` 을 주지 않으면 **한글 설명이 깨진다** → spawn 시 항상 지정.
- **`WSAEADDRINUSE` (임시 포트 고갈)** — 개발 PC 실측(2026-08-11): 동적 포트 범위가
  **1024–14999 (13,977개)** 로 좁게 설정돼 있고, `PFComAgent.exe` 가 **127.0.0.1 로 26,416개** 연결을
  물고 있어(루프백은 연결당 포트 2개 소모) 범위가 사실상 100% 소진된 상태였다.
  → **앱 코드 문제가 아니라 PC 환경 문제.** 연결이 계속 churn 하므로 빈 포트가 있을 때와 없을 때가 갈려
  **간헐적으로** 실패한다. 대응:
  ① 연결 단계 실패(`WSAEADDRINUSE`/`Connect to server failed`)는 **3회 지수 백오프 재시도**.
     연결 전 실패는 요청이 서버에 닿지 않았다는 뜻이라 쓰기 작업(`change -i`)도 재시도가 안전하다.
     연결된 뒤의 실패는 재시도하지 않는다(중복 생성 위험).
  ② p4 는 **연결 실패에도 exit 0** 으로 끝나는 경우가 있어 종료코드만 보지 말고 **출력 내용도 검사**한다.
  ③ 워크스페이스 루트를 캐시해 호출 수를 줄인다.
  ④ 최종 실패 시 원인(임시 포트 고갈)을 짚어주는 메시지를 보여준다.
- 접속 정보(P4PORT/P4USER)는 PC 설정과 다를 수 있어 앱 설정에서 덮어쓸 수 있다.

### 3.4 디스크 정리 모듈 ⚠️데스크톱 전용

Unreal Engine + C++ 로 개발하는 PC 는 **빌드 산출물과 캐시가 원본보다 커진다**. 실측(사내 UE 프로젝트
한 개): 786GB 중 Intermediate 224.9GB · DerivedDataCache 계열 151.3GB · `.vs` 77.8GB — 규칙만으로
435GB 가 "지워도 되는 것" 으로 잡힌다. 이 모듈은 그것을 찾아 **휴지통으로** 보낸다.

**화면 구성** (TreeSize 를 참고했다)

| 뷰 | 내용 |
|---|---|
| 드라이브 | 고정 디스크별 사용량 막대. 90% 넘으면 빨강 |
| 폴더별 용량 | 트리 + 부모 대비 비율 막대 + 파일 수. 눌러서 드릴다운 |
| 정리 후보 | 규칙 판정(안전/주의/보존) · 종류가 같은 것은 한 줄로 묶음 · 체크해서 삭제 |
| 파일 종류별 | 확장자 집계 (`.uasset` `.obj` `.pdb` …) |
| 마지막 수정 시점 | 1주/1개월/3개월/6개월/1년/그 이상 구간별 용량 |
| 가장 큰 파일 | 단일 파일 Top 100 |
| 오래된 폴더 | 6개월 넘게 안 건드린 큰 폴더 |
| 중복 파일 | 같은 내용 파일 묶음 (크기 → 앞 64KB → 전체 해시 순으로 좁힘) |

**판정 규칙** — `electron/disk.js`. 세 단계: `safe`(도구가 자동 재생성) · `caution`(재생성되지만
재빌드·재다운로드 비용) · `keep`(원본·설정·세이브·버전관리 메타).

- UE 프로젝트/엔진 안: `Intermediate` · `DerivedDataCache*` · `.vs` · `Saved/{Logs,Crashes,Cooked,StagedBuilds}` = safe /
  `Binaries` · `Saved/{Autosaves,Backup}` = caution
- 전역 캐시: 공유 DDC · 셰이더 캐시(D3D/NVIDIA/AMD) · AutomationTool 로그 = safe / Zen 스토어 · VaultCache = caution
- 언제나 보호: `Source` `Content` `Config` `Plugins` `Saved/SaveGames` `Saved/Config` `.git` `.p4`,
  시스템 폴더, 드라이브 루트, 스캔 루트 자신

**AI 판단** — 사내 LLM(§3.3 과 같은 접속 정보)에 경로·크기·수정시각만 보낸다(**파일 내용은 보내지 않는다**).

> ⚠️ **AI 는 판정을 조이기만 한다.** 규칙이 `caution` 이라고 본 것을 모델이 "안전" 이라 해도 `caution` 으로
> 남고, 규칙이 모르는 폴더는 모델이 뭐라 하든 `caution` 이 상한이라 기본 선택되지 않는다.
> 모델이 헛것을 말해도 사용자 데이터가 지워지지 않는 것이 이 모듈의 제1 요건이다.

**삭제** — 언제나 **휴지통**(`shell.trashItem`)이다. 영구 삭제 경로는 만들지 않는다. 화면이 보낸 목록은
믿지 않고 main 에서 다시 검증한다(이번 세션에 스캔한 루트 안인지 + 보호 대상 아닌지).

**성능** — 실측 84만 파일 786GB 스캔에 91초(약 9,200 파일/초). 스캔은 **중간중간 이벤트 루프에 양보**한다 —
동기로 돌리면 그동안 main 이 IPC 를 못 받아 취소 버튼과 진행 표시가 죽는다.

## 5. 아키텍처 & 데이터 흐름

데이터를 **2계층**으로 나눈다. 회사 업무 정보는 클라우드에 올리지 않는 것이 원칙.

**① 개인 데이터 (클라우드 저장 · PC+모바일 공용)**
구글 캘린더 · intervals.icu → **Supabase Edge Function(cron)** 이 주기적으로 당겨와 Supabase DB에 저장 → PC/모바일에서 조회. **PC가 꺼져 있어도 모바일에서 최신 조회 가능.**

**② BTS 이슈 목록 (데스크톱 전용 · 비저장)**
사내 Redmine · 회사 JIRA → **Electron main 프로세스(Node, `electron/bts.js`)** 가 앱에서 요청할 때 **실시간으로 직접 조회** → 데스크톱 화면에만 메모리로 표시. **DB/클라우드에 저장하지 않고, 모바일에도 표시하지 않음.** 앱을 닫으면 사라진다.
여기서 사용자가 ‘진행 중인 업무’로 끌어다 놓은 항목만 계층 ①(클라우드)로 넘어간다.

```
  ── 계층 ① 개인 데이터 (클라우드) ───────────────────────
   [Google Calendar]            [intervals.icu]
           \                        /
       ┌───────────────────────────────────────┐
       │  Supabase Edge Function (cron)          │  주기 동기화
       └────────────────────┬────────────────────┘
                            ▼
                   Supabase (Postgres)  ← 개인 데이터만 저장
                            │  (읽기)
                 ┌──────────┴───────────┐
             PC 앱 (Electron)      모바일 (PWA)
                 ▲
                 │  ── 계층 ② 회사 업무 (데스크톱 전용, DB 거치지 않음) ──
                 │
          [Redmine(사내망)]     [JIRA(클라우드)]
                 └─────────┬─────────┘
             Electron main(Node) 실시간 조회 → 데스크톱 UI에만 표시
```

**데스크톱 셸은 화면을 담지 않는다 (2026-08-11 결정)**
Electron 은 창·트레이·전역 단축키와 로컬 권한이 필요한 일(p4 CLI, 사내망 BTS/LLM, safeStorage)만 맡고,
화면은 **Cloudflare 에 배포된 웹을 그대로 불러온다** (개발 중에는 Vite dev 서버). 그래서 UI 를 고쳐도 exe 를
다시 만들 필요가 없고, PC·모바일이 항상 같은 버전을 본다. preload 는 주소와 무관하게 붙으므로 원격 화면에서도
`window.desktop` 브리지가 동작한다 — 대신 그 브리지가 원격 페이지에 열려 있으므로 **창이 저장된 주소 밖으로
이동하지 못하게 막는다**(외부 링크는 기본 브라우저로). 주소는 설정 → 앱 주소, `MEOS_APP_URL`, 또는 첫 실행
안내 화면에서 정한다.

- **모바일에 보이는 것**: 캘린더 · 운동 · 리포트 · **업무 화면(진행 중인 업무 · 할 일 · 루틴)** · (업무 위젯 제외한) 대시보드.
- **데스크톱에만 보이는 것**: 업무 화면의 **BTS 섹션**, 바로가기 독 · 스니펫, 대시보드의 업무 위젯.
  모바일에서 업무 화면을 열면 BTS 카드 자리에 "PC에서만 조회" 안내가 뜨고 나머지는 그대로 쓸 수 있다.
- Redmine은 사내망에서만 접근 가능한데, 어차피 **데스크톱(사내 PC)에서만 실시간 조회**하므로 제약과 설계가 자연스럽게 일치한다.

## 7. 데이터 모델 (intervals.icu 응답 실측 반영)

클라우드 DB에는 **개인 데이터만** 저장한다. (intervals.icu 필드명은 2026-07-13 실측 기준)

- `events` — 캘린더 일정 (source=google)
- `activities` — intervals.icu `/activities`
  - `id`, `type`, `name`, `start_date_local`, `distance`, `moving_time`, `average_speed`(→페이스 환산), `average_heartrate`/`max_heartrate`, `calories`, `icu_training_load`, `device_name`
- `wellness` — intervals.icu `/wellness` (일자별 컨디션 + 훈련부하)
  - `id`(날짜), `ctl`(=Fitness), `atl`(=Fatigue), **`form` = ctl − atl (=TSB, 계산값)**, `hrv`, `restingHR`, `sleepSecs`, `sleepScore`, `steps`, `weight`, `vo2max`
- `gear` — 러닝화 및 누적 마일리지 ⚠️ **소스 미정** (§9 — intervals.icu에 gear 데이터 없음)
- `body_checks` — 몸상태 판단 (하루 한 건, 0018)
  - `level`('good'|'caution'|'bad') + `flag_count`, `signals`(판단 당시 값·기준을 통째로 박아 둔 jsonb),
    `answers`(다리 무거움·뻣뻣함·통증), `recovery_until`(가민 회복 시간이 끝나는 시각)
- `reports` — 자동 주간/월간 요약 스냅샷 (개인 데이터만, 업무 제외)
- `sync_state` — 소스별 마지막 동기화 시각/상태
- `work_items` — 진행 중인 업무 + 할 일 (한 테이블, `list`로 구분 → 서로 이동은 컬럼 값 변경)
  - `list`('progress'|'todo'), `status`('wait'|'doing'|'done'), `title`, `url`, `done`, `sort`
  - `origin`('manual'|'bts') + `bts_system`/`bts_issue_id`/`bts_tracker`/`bts_version` — BTS에서 끌어온 항목
  - `deleted_at` — 휴지통(soft delete). 같은 BTS 이슈 중복 등록은 부분 유니크 인덱스로 막는다
- `routines` — 루틴. `last_done_on`(date)이 오늘이면 완료 → 날짜가 바뀌면 자동 리셋. `deleted_at` 로 휴지통

> Form/TSB는 intervals.icu에 별도 필드가 없어 **`ctl − atl` 로 계산**한다. 페이스도 `distance ÷ moving_time` 으로 환산.
> **BTS 이슈 목록 자체는 테이블을 두지 않는다.** 데스크톱에서 실시간 조회해 메모리로만 표시하고 앱 종료 시 사라진다.
> `work_items` 에 남는 건 내가 직접 끌어다 놓은 항목뿐이다 (§2 원칙 변경 참고).

## 8. 보안 / 시크릿

- 클라우드에서 쓰는 토큰(Google OAuth, intervals.icu): **Supabase secrets / 암호화 저장**.
- **회사 업무 토큰(JIRA, Redmine API Key)은 데스크톱에만 보관** — Electron OS 키체인(safeStorage). 클라우드로 전송하지 않음.
- **AI 서밋 로그는 사내 LLM 만 쓴다.** 소스코드(diff)가 사외로 나가면 안 되므로 Anthropic API 같은
  외부 API 는 쓰지 않는다. `llm.aquatree.games` 는 사내망 안이라 diff 를 통째로 보내도 회사 밖으로 나가지 않는다.
  LLM API 키는 데스크톱 safeStorage 에만 보관한다.
- **AI 코드 리뷰는 사외 모델을 선택적으로 허용한다** (2026-08-14, 위 2026-08-07 판단 변경).
  검수는 작성한 것과 다른 모델이 봐야 의미가 있어서 사용자가 Codex/Claude 를 고를 수 있게 했다.
  대신 ①기본값은 사내 LLM 하나뿐, ②리뷰어마다 `사내`/`사외` 를 화면에 표시, ③사외가 켜져 있으면
  실행 전에 "코드가 회사 밖으로 전송된다" 고 경고한다. **서밋 로그 경로는 그대로 사내 LLM 전용이다.**
  두 CLI 는 API 키가 아니라 구독 로그인으로 돌린다(키를 앱이 들고 있지 않는다).
- **BTS 이슈 목록과 접속 토큰은 클라우드로 전송하지 않는다.** 다만 내가 진행 중인 업무로 끌어다 놓은 항목의
  이슈번호·제목·트래커·목표버전은 `work_items` 에 저장된다 (§2 원칙 변경, 2026-08-07).
- 클라이언트는 개인 데이터 접근 시 Supabase Auth 세션(매직링크 로그인)만 사용(토큰 미보유).

## 9. 리스크 / 미결 사항

- **BTS 섹션은 데스크톱에서만·실시간**: 앱을 켜야 최신 조회(캐시/오프라인 없음). 모바일 미노출은 설계 의도.
  진행 중인 업무·할 일·루틴은 클라우드에 있으므로 모바일에서도 그대로 보인다.
- **러닝화(gear) = Garmin 별도 연동(후순위)**: intervals.icu엔 이 계정 Garmin 장비가 안 넘어옴(확인됨; gear는 Strava 경유만). → Garmin에서 직접 가져오되 **v1 이후로 미룸**. Garmin 공식 오픈 API 부재 → 비공식 라이브러리(`garminconnect`/`garth`) + 계정 인증 필요 → 구현 방식(Electron Node vs 파이썬 사이드카) 추후 결정.

**확정된 결정**
- 로그인: **Supabase Auth 매직링크**(이메일 링크).
- intervals.icu API Key: **발급 완료 + 응답 필드 검증 완료(2026-07-13)**.
- 업무 조회 범위: **내 담당 & 열린 이슈** (Redmine `status_id=open`, JIRA `statusCategory != Done`).
- **BTS 접속 정보는 설정 화면에서 입력**하고 데스크톱에만 OS 암호화(safeStorage)로 저장.
  개발 편의로 저장소 루트 `.env.local` 의 `REDMINE_URL`/`REDMINE_API_KEY`/`JIRA_URL`/`JIRA_EMAIL`/`JIRA_API_TOKEN` 을 폴백으로 읽는다.
- BTS에서 끌어온 진행 중인 업무 항목은 **클라우드 저장**(§2 원칙 변경, 2026-08-07 사용자 결정).
- 운동 화면: 러닝화(장비)는 기본 숨김·버튼으로 표시하고, 그 자리에 **Fitness(CTL/ATL/TSB) 그래프**를 기본 표시 (§3.1).
- **데스크톱 앱은 배포된 웹을 띄운다**(2026-08-11). exe 는 `npm run dist:win` 으로 만들고(설치본 + 포터블),
  설정값은 개발 모드와 같은 `%APPDATA%\@pp\desktop` 을 공유한다. UI 수정은 재배포만으로 반영된다.
- **월간 훈련 캘린더 + 훈련 상세**(2026-08-12, `reference/1.png`·`5~7.png` 참고). 운동 화면에 월별 달력을 두고
  하루 훈련의 거리·세션 종류를 보여준다. 항목을 누르면 `/activity/:id` 로 가서 요약 · **랩 분석** · **데이터 추이**
  (심박수/페이스/케이던스/파워/수직비율)를 본다. 랩·스트림은 DB 에 저장하지 않고 Edge Function `activity` 가
  intervals.icu 에서 그때그때 가져온다(700포인트로 다운샘플, 약 50KB). **세션 종류는 활동 이름에서 추정**한다
  (규칙 기반 — `lib/session.ts`). **틀리면 상세 화면에서 직접 고를 수 있다**(`activities.session_kind`,
  0008 마이그레이션). 지정하면 캘린더 색과 규칙 기반 분석의 목표 심박대가 함께 바뀌고,
  "자동으로 되돌리기" 로 이름 추정으로 돌아간다. 동기화는 upsert 로 지정 컬럼만 덮으므로 값이 살아남는다.
  앞으로의 훈련 계획 표시는 아직 넣지 않았다.
- **동기화는 Edge Function 한 벌**(2026-08-11, `supabase/functions/sync`). 로컬 동기화 서버(`server/`)와
  Node 판 코어(`scripts/sync-core.mjs`)는 **삭제**했다 — 같은 로직을 두 벌 들고 있으면 반드시 어긋난다.
  CLI(`npm run sync`)도 이제 함수를 호출만 한다. 호출자는 세 갈래:
  앱=사용자 JWT / CLI=service_role 키 / cron=Vault 에 넣은 service_role 키.
  기본은 **최근 60일**만 당기고, 과거 전체는 `full` 옵션(운동 화면 "전체 기간" 버튼 · `npm run sync:full`).
- **몸상태 판단**(2026-09-15, `lib/bodyCheck.ts` · 0018). 운동 화면 "컨디션 / 웰니스" 카드에서 누르면
  다섯 신호로 오늘 훈련해도 되는지 판정한다: ①가민 회복 시간이 남음 ②수면 6시간 미만
  ③HRV 가 **직전 7일 평균** 대비 10% 이상 하락 ④안정시심박이 **평소(직전 28일 중앙값)** 보다 3bpm 이상 상승
  ⑤주관적 신호(다리 무거움·국소 뻣뻣함·통증 — 질문지). 켜진 신호 0개=좋음 🙂 / 1~2개=주의 😐 / 3개 이상=나쁨 😣.
  판정은 **운동 화면 훈련 캘린더와 캘린더 화면 양쪽에 아이콘**으로 찍히고, 누르면 그날 리뷰가 뜬다.
  ⚠️ 판단 근거(`signals`)를 저장 시점 값으로 박아 둔다 — 웰니스가 나중에 다시 동기화돼도 과거 아이콘이
  슬그머니 바뀌면 안 된다. 데이터가 없는 신호는 '판단 불가' 로 빼고 세지 않는다.
- **가민 회복 시간은 API 로 가져올 수 없다**(2026-09-15 직접 확인). Forerunner 255 는 Training Readiness
  미지원이라 `/metrics-service/metrics/trainingreadiness/{날짜}` 가 빈 배열이고, `trainingstatus/aggregated` ·
  `usersummary/daily` · `hrv-service` · 활동 상세 어디에도 `recoveryTime` 이 없다(활동엔 `recoveryHeartRate` 뿐).
  **원본 FIT 파일까지 받아 파싱**해도 session 메시지에 회복 시간이 없다 — 가민이 서드파티에 넘기기 전에
  비공개 필드를 지운다. intervals.icu 의 활동/웰니스 183개 필드에도 없다.
  → 시계에 뜬 값을 질문지에서 한 번 받아 **끝나는 시각**으로 저장하고, 다음 판단 때 남은 시간을 계산해
  기본값으로 채운다. 그 사이 새 활동이 있으면 "시계를 한 번 보라" 고 알린다.

## 10. 로드맵 (제안)

- **Phase 0** — 스캐폴딩: 모노레포(web / electron / supabase), Supabase 프로젝트 + Auth(매직링크) + 스키마.
- **Phase 1** — intervals.icu 연동 + **운동 모듈** (가장 독립적, 데모가 빠름). Fitness 그래프 + 러닝화 토글 포함.
- **Phase 2** — Google Calendar 연동 + **캘린더 모듈**.
- **Phase 3 ✅ (2026-08-07)** — 사내 Redmine + 회사 JIRA 실시간 조회 + **업무 모듈**(진행 중인 업무 · BTS · 할 일 · 루틴) + **휴지통**.
- **Phase 4** — **대시보드 홈** 위젯 통합 (모바일은 업무 위젯 제외).
- **Phase 5** — **리포트 자동 요약** (개인 데이터 기준).
- **Phase 6 ✅ (2026-08-11)** — PWA + 배포. Cloudflare Workers(GitHub 연동) 자동 배포, 비밀번호 로그인,
  데스크톱 패키징(`npm run dist:win` → 설치본 + 포터블). 데스크톱은 배포된 웹을 띄우는 셸로 전환 (§5, §11).
- **(후순위)** — Garmin 장비 연동 → 러닝화 마일리지 채우기 (인증/구현 방식 결정 후, §9).

## 11. 모바일 (Android) — PWA

**웹 코드를 그대로 쓴다.** 별도 앱 코드 없음. `vite-plugin-pwa` 로 manifest + 서비스워커를 붙이고,
`web/dist` 를 정적 호스팅에 올린 뒤 Chrome 에서 홈 화면에 추가하면 전체화면 앱으로 실행된다.

- **모바일 사용 가능**: 업무(진행 중인 업무 · 할 일 · 루틴) · 캘린더 · 운동 · 리포트 · 휴지통
- **PC 전용**(자동으로 숨김 또는 안내로 대체): BTS · Perforce · 디스크 정리 · 바로가기 · 스니펫 · Quick Search
- **하단 탭바** — 모바일에서 사이드바가 하단 고정 탭바로 바뀐다(엄지 도달 범위).
  `env(safe-area-inset-bottom)` 로 제스처바를 피한다.
- **로그인** — `emailRedirectTo` 가 이미 `window.location.origin` 이라 코드 변경 없이 동작한다.
  단 **Supabase Redirect URLs 에 배포 주소 등록 필수**.
- **아이콘** — 디자이너가 준 **컨택트 시트**(`icons/*.png`, 마젠타 배경에 여러 크기 배치)에서
  `scripts/make-pwa-icons.mjs`(`npm run icons`)가 자동 추출한다. 시트를 교체하고 재실행하면 끝.
  - 마젠타가 아닌 덩어리를 찾아 가장 큰 아이콘 선택(라벨 글자는 크기·비율로 걸러냄)
  - 크로마키로 마젠타 제거. 경계 픽셀은 `C = (P − BG·(1−a)) / a` 로 배경 성분을 걷어내고,
    **리사이즈 후 되살아나는 잔상까지 한 번 더 청소**한다(알파가 낮은 픽셀에서 이 나눗셈이 오차를 키움)
  - 시트별 용도: android→PWA, favicon→브라우저/iOS, window→Electron 창·트레이
- **maskable 규칙** — 런처가 원형/사각으로 잘라내므로 **투명 영역이 있으면 아이콘이 작게 떠 보인다.**
  배경을 꽉 채우고(완전 불투명), 링·글자는 안전영역(중앙 80% 원) 안에 두며 모서리만 잘리게 한다.
  실측: 링·글자 최대 반경 199px < 안전영역 205px 이라 여백 6% 로도 안전.
- **캐시 정책** — 정적 자산만 precache. Supabase 응답은 캐시하지 않는다
  (오래된 데이터 표시 방지 + 인증 토큰이 캐시에 남는 것 방지).

> **APK 가 필요해지면** Capacitor 로 같은 `web/dist` 를 감싸면 된다. PWA 작업이 그대로 재사용된다.

> ⚠️ **알려진 이슈 — Electron 패키징 시 자산 경로**
> PWA 를 위해 `base: '/'` 를 쓰므로 `dist/index.html` 의 자산 경로가 `/assets/…` 절대경로다.
> 개발 중에는 Electron 이 `localhost:5173` 을 로드해 문제없지만, **패키징(Phase 6) 후
> `loadFile()` 로 `file://` 로 열면 절대경로가 깨진다.** 패키징 시 커스텀 프로토콜(`app://`)
> 등록이나 로컬 서버 방식으로 해결해야 한다.
